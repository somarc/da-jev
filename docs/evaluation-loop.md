# The field-lab evaluation loop

Use a small, finite evaluation to improve the composition of a frontier model,
Jev, da-cli and QMD. This is a protocol over existing tools, not a new task engine,
autonomous scheduler, credential mechanism or publication authority.

## Ownership

| Surface | Owns | Does not prove |
| --- | --- | --- |
| Frontier model and operator | Task framing, reviewed criteria, analysis, escalation | That its own assertion is correct |
| Jev | Narrow semantic judgments over explicit state and closed candidates | Permission, targets, command arguments, task completion |
| Deterministic controller | Allowed operations, bindings, bounds and response checks | That an allowed operation answers the objective |
| da-cli | Its declared source/delivery/domain contracts | Decorated browser behavior or independent semantic acceptance |
| QMD | Bounded command outcomes and evidence references | A full trace, task success or permission to replay |
| Field-lab site | Inspectable, sanitized retained records | A visitor-triggered model or CLI execution |

## One finite cycle

1. **Choose the question and the stop.** Prefer one coherent decision context per
   state. Several related questions can share that state. Do not use a model for
   deterministic parsing, exact identity or permission checks.
2. **Verify the actual runtime.** Record the installed release, registry integrity,
   verified first-party bytes, Node version, target, code branch and source path.
   Resolve the external DA workspace; check auth before operational work. A version
   string, ancestor Git SHA or old artifact is not enough.
3. **Freeze before inference.** Retain cases, candidate text/order, expected route
   preferences, any independently reviewed acceptance criteria, model version,
   question/state construction, budget, comparison arms and protocol digest outside
   Git. Distinguish reused diagnostic cases from genuinely unseen cases.
4. **Observe without chasing success.** Keep every planned answer and service error.
   No post-result label changes, unlimited prompt passes or silent retries. Request
   IDs and original broker-returned bodies remain separate from normalized records.
5. **Execute only bounded code-owned selections.** Keep explicit `--qmd` on DA
   operations. Metadata help may intentionally produce no receipt. No model-supplied
   argv, target, credential, permission or `next[]` is executable policy.
6. **Verify at each owning surface.** Separate answer validity, preferred-route
   agreement, operation result, task evidence, receipt durability and browser proof.
   A correct refusal is not an operational defect. Missing proof stays unknown.
7. **Classify the friction before filing.** Assign protocol/state, model, harness,
   CLI, QMD, platform/service or auth/environment ownership. Reproduce a concrete
   boundary, search existing issues and review sanitized evidence. Reuse da-cli's
   packaged receipt-friction harvester where appropriate; do not build a second
   always-on collector or automatically promote its hypotheses to issues.
8. **Close the learning loop.** Link the observation to a regression, reviewed fix,
   exact adopted release and a later comparable check. Preserve negative results.
   Update upstream project state only if evidence changes the next-work order.
9. **Publish a separate reviewed projection.** DA owns authored pages and datasets;
   Git owns code and this protocol. Review exact source bytes and target paths,
   dry-run writes, verify source read-back and preview, then separately authorize
   live publication. Do not treat a successful experiment as release approval.

## Measurements that must remain separate

- Route preferences are not a complete acceptance oracle: a broader operation may
  supply useful proof while differing from a frozen label.
- Confidence/distribution concentration is not correctness or permission.
- API upstream time is not client round-trip time or end-to-end task latency.
- CLI process time includes QMD work but excludes preparation and orchestration.
- Record token counts, request counts and the exact price basis before discussing
  model-input cost. A larger number of isolated requests can cost more than a
  batched protocol even when each state is smaller.
- Acceleration requires a comparable frontier-only workflow, equivalent evidence
  and task criteria, and full workflow measurements. Until then it is unmeasured.
- Independent task-acceptance infrastructure remains with its owning upstream
  session/repository. Do not implement a competing projection in the lab.

## Resume without repetition

Read the current runtime, target and external protocol/run files first. Separate
setup calls, synthetic regressions, planned inference and selected operations.
Completed reads and mutations are not replayed to repair a journal or invent a
missing record. A genuinely new read has its own scope and observation time.
An uncertain mutation requires reconciliation, not retry-by-default.

The current small runner can execute the same read for two different objectives.
Count those observations honestly; do not retroactively pretend they were a single
snapshot. Any future reuse must explicitly bind the observation time, target,
source identity and freshness policy and remain a new reviewed protocol change.
